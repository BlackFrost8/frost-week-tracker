# Getting Frost onto Google Play

The Android app is a **Trusted Web Activity (TWA)**. It's a small native app,
generated by Google's Bubblewrap, that opens `planner.froststudio.org` full
screen in Chrome, with no address bar. That means:

- **One codebase.** Every web deploy updates the Android app too. Rebuild the
  Android app only to upload a new version to Play, or when something in
  `android/` changes.
- **Sign-in, Calendar, offline mode and account deletion** all work the same
  way they do on the web.
- **What it costs:** native-only features (home-screen widgets, for example)
  aren't possible in a TWA. Moving to Capacitor later is possible, and keeping
  the same package name and signing key lets it ship as an update.

**Package name:** `org.froststudio.planner`. This can never change once the
app is uploaded.

## What you do, in order

### 1. Merge to `main`

That deploys the web changes: manifest, offline mode, account deletion and the
deletion page. The TWA opens the live site, so the site has to have these first.

### 2. Make an upload key (once, about 2 minutes)

This key proves your uploads come from you. Google holds the separate key that
signs what users actually download ("Play App Signing").

`keytool` comes with any Java JDK, and Android Studio includes one. Run:

```bash
keytool -genkeypair -v -keystore upload-keystore.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
```

It asks for a password and a name. **Store the `.jks` file and the password
in a password manager.** Never commit it; `android/.gitignore` already blocks
`.jks` files. If it's ever lost, Play support can reset the upload key, but
that takes days.

### 3. Give the key to GitHub Actions

On GitHub, go to **Settings → Secrets and variables → Actions → New repository
secret** and add four secrets:

| Secret | Value |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | Output of `base64 -w0 upload-keystore.jks` (macOS: `base64 -i upload-keystore.jks`; Windows PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("upload-keystore.jks"))`) |
| `ANDROID_KEYSTORE_PASSWORD` | The keystore password |
| `ANDROID_KEY_ALIAS` | `upload` |
| `ANDROID_KEY_PASSWORD` | The key password. Usually the same as the keystore password. |

### 4. Build the bundle

Go to **Actions → Android app → Run workflow** (on `main`). When it finishes,
download the `frost-android-N` artifact. It contains:

- `app-release.aab`: this is what you upload to Play
- `app-release.apk`: for installing directly on your own phone to test

Each run's number becomes the `versionCode`, so every build is uploadable.

### 5. Create the app in Play Console

1. **Create app**: name *Frost Week Tracker*, default language English, type
   *App*, *Free*.
2. **Policy → App content**: answer everything using `store/LISTING.md`
   (privacy policy, ads, app access with a test account, content rating,
   target audience 13+, Data safety). The account deletion URL is
   `https://planner.froststudio.org/delete-account.html`.
3. **Grow → Store listing**: paste the text from `store/LISTING.md` and
   upload the files in `store/graphics/`.

### 6. Upload to internal testing first

Go to **Test and release → Testing → Internal testing → Create release**,
upload the `.aab`, and add yourself as a tester. Accept **Play App Signing**
when it asks.

### 7. Connect the app to the site (Digital Asset Links)

Until this step is done, the app shows a browser address bar at the top.

1. Go to **Play Console → Test and release → Setup → App signing**.
2. Copy the **SHA-256 certificate fingerprint** under *App signing key
   certificate*.
3. Put it in `public/.well-known/assetlinks.json` in place of the
   placeholder. To make a directly installed test APK verify as well, add the
   *Upload key certificate* fingerprint as a second entry in the same array:
   ```json
   "sha256_cert_fingerprints": [
     "AB:CD:…app signing key…",
     "12:34:…upload key…"
   ]
   ```
4. Commit to `main` (that deploys it), then check
   `https://planner.froststudio.org/.well-known/assetlinks.json` loads.

Play Console also has a ready-made file under **Grow → Deep links**, which
you can copy instead.

### 8. Test on a real phone

Install from the internal testing link, then check:

- [ ] It opens full screen, with no address bar (if there is one, revisit step 7)
- [ ] **Continue with Google** signs in. If the popup misbehaves inside the
      app, *use an email and password instead* is the fallback, and please
      report what happened.
- [ ] A task added on the phone appears on the web, and the other way round
- [ ] Airplane mode: the app still opens and shows your week

**Don't try *delete account* on your own account.** It is permanent. It only
runs if someone opens it, types `delete` and confirms with Google, so it can
never fire by accident. Play requires it to exist; nobody requires you to
press it.

### 9. Closed testing (if your developer account is new)

Personal developer accounts created after November 2023 must run a **closed
test with at least 12 testers, opted in for 14 days in a row**, before they
can apply for production. Friends, classmates and family count. Create the
track under **Testing → Closed testing**, share the opt-in link, and keep
pushing small updates during the 14 days. After that, apply for production
access from the dashboard.

### 10. Production

Promote the tested release to **Production**. The first review typically
takes a few days.

## Updating the app later

- **Web changes**: nothing to do. They reach the app with the normal deploy.
- **Android changes** (icon, name, colours, the `android/` project): run the
  *Android app* workflow and upload the new `.aab`. Bump `versionName` in
  `android/app/build.gradle` when you want users to see a new version
  number.
- **Regenerating the project**: `android/twa-manifest.json` holds Bubblewrap's
  settings, so `bubblewrap update` can rebuild from it. Afterwards, re-apply
  the signing block and `versionCode` line in `app/build.gradle`.

## Known limits

- **Google Calendar connection:** until Google verifies the OAuth consent
  screen (see ROADMAP §2.4), connecting shows an "unverified app" warning and
  is capped at 100 new users. That applies to the app and the web alike.
- **Phone layout:** the four row buttons on each task (group, edit, move,
  delete) are tight on small phones. An overflow menu would be better. It
  works as it is, but it's the next mobile polish item.
